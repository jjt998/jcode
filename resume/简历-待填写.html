项目简介：从 0 设计并实现的一个轻量本地 Coding Agent，覆盖「命令行入口 → 运行时装配 → 原生工具调用循环 → 结构化上下文构建 → 工具安全治理 → 子 Agent 编排 → 分层记忆 → 运行证据与 Checkpoint 恢复」完整链路，可通过 CLI 与本地 Web 控制台两种方式驱动。
核心工作
  • 主链路架构设计　独立完成 Agent 运行时分层设计，按 app / runtime / context / tools / policy / state / memory / workers / evidence / providers 十层拆分职责边界，明确「装配—执行—治理—留痕」四类关注点分离，将约 8,200 行代码控制在单模块可读范围内，避免核心链路互相耦合。
  • 原生工具调用循环　基于 DeepSeek / MiniMax 的 openai_responses 协议实现原生 Function Calling 循环，注册 17 个内置工具（文件读写、精确文本补丁、目录列举、内容检索、Shell 执行、Todo 管理、用户澄清、Plan Mode、子 Agent 创建/通信/等待）；工具参数 Schema 由 Pydantic Model 自动生成，校验失败直接回传结构化错误，不做静默兜底或自动修正。
  • 上下文工程与分级压缩　设计 prefix / skill / history / working_memory / tools 五段式结构化上下文（ContextResult），统一编译为 ProviderInputSnapshot 供 Provider 调用、预览与审计三方共用同一快照；设计四级上下文压缩策略，当可治理压力达到 95% 时触发摘要流程——先将 History 落盘为 artifact 并验签，再按固定 JSON Schema 生成摘要，校验最终容量后原子提交，杜绝静默截断与信息丢失。
  • 工具安全治理链　设计并实现固定 10 步工具执行链：工具查找 → 参数校验 → 重复调用拦截 → 行为策略检查 → 权限检查 → Sandbox 检查 → 执行 → 工作区变更检测 → 结果脱敏 → 证据落盘。覆盖路径逃逸、未读先写、重复调用、Shell 超时、Sandbox 拦截、敏感信息脱敏等 7 类安全场景，保证 Agent 的每一次文件写入与命令执行都可追溯。
  • 分层记忆与子 Agent 编排　实现 Working_Memory（回合内推理状态）/ Daily Log（过程日志）/ Durable Memory（长期结论）三层记忆体系，回合结束自动将过程信号整理沉淀为长期知识，并对密钥、Token、Password 等敏感特征做过滤拦截；实现 worker / Explore / plan mode 三类子 Agent 语义，子 Agent 继承父级工作区、工具策略与权限模型，结果回流至父级 Working Memory 而非直接成为最终回答，保证主循环对结果的最终裁决权。
  • 运行可观测与断点恢复　每次运行落盘 trace.jsonl（逐事件轨迹）/ task_state.json（任务状态）/ checkpoint.json（含工作区指纹的恢复点）/ report.json（运行汇总）四类运行证据，支持基于 Checkpoint 的会话恢复与跨 Run 事件流审计；自建评测 Harness（replay / scorer / manifest / baseline），对 Agent 行为做可复现的回归度量。
  • 本地 Web 控制台　基于 FastAPI + Uvicorn 实现单用户本地 Web 控制台，以本地仓库为项目单位组织工作区，支持浏览历史会话、新建会话与继续对话、实时观察工具执行日志与上下文容量占用。
  • 工程规范与协议治理　建立显式协议版本管理机制（Session schema v6 / Working Memory v3 / Checkpoint schema v5），明确拒绝为旧协议做迁移兼容，从源头控制技术债；配套输出 65 份设计文档与 106 个自动化测试用例，覆盖上下文预算、压缩摘要、工具守卫、Provider 连续性、Checkpoint 等核心路径。
