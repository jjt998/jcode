安装后如何启动和使用 JCode

核心问题：安装完成后，你得到的不是一个正在运行的服务，而是一个已经登记到 Python 环境里的命令行工具。

先进入项目根目录

cd D:\1technical_stack_study\agent_study\agent_projects\jcode

JCode 会读取当前工作目录下的项目文件和配置。它还会在运行时写入 .jcode/ 目录，用来保存 run trace、session、memory、checkpoint 和 report。

当前源码布局下的启动方式

按当前项目实际结构，源码包名是 src，所以最可靠的启动方式是：

& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m src --help
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m src "hi"

常用方式：

& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m src --cwd . "帮我查看项目结构"
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m src --resume latest "继续"
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m src --session-id demo-session "实现一个小功能"
README 里写的是 jcode "hi" 和 python -m jcode --help。这代表项目作者希望包名是 jcode。但当前文件实际在 src 包下，因此现阶段应优先使用 python -m src。

如果打包配置修好以后

如果以后把源码包和 pyproject.toml 对齐，让包名真的变成 jcode，那么安装后就可以按 README 使用：

jcode "hi"
python -m jcode --help

在 PowerShell 中，如果 jcode 命令找不到，但安装确实成功，通常是当前 shell 还没刷新 PATH。可以重开一个 PowerShell，或者直接用完整 Python 命令。

为什么安装后可以这么用

pip install -e . 会把当前项目登记到这个 Python 环境中。登记完成后，Python 解释器就知道：当你导入或运行这个包时，应该去项目源码目录里找代码。

editable install 的特别之处是：它不是把源码复制一份到环境目录，而是建立一个指向源码目录的开发安装关系。因此你修改源码后，下一次启动通常会直接用新代码。

如果 pyproject.toml 里配置了命令行入口，例如：

[project.scripts]
jcode = "jcode.app.cli:main"

pip 还会在该 Python 环境的 Scripts 目录下生成一个命令脚本。这个脚本的职责很简单：当你输入 jcode 时，它会导入 jcode.app.cli，然后调用里面的 main() 函数。

JCode 启动后做什么

结合项目说明，启动后会进入这条主链路：

命令行入口
-> app.bootstrap 装配运行时
-> runtime.agent 进入 Agent 主循环
-> 构建上下文
-> 调用模型或跳过真实请求
-> 执行工具
-> 写入 .jcode/ 运行证据
-> 输出最终回答

如果你配置了 .jcode.toml 或环境变量里的 API key，它会尝试真实调用模型服务。如果没有 API key，README 说明它仍会构建上下文并写入运行证据，但不会发送真实模型请求。

小练习

安装后输入 jcode 能启动，本质上是因为 pip 做了哪件事？

查看答案

pip 根据 pyproject.toml 生成了命令行入口脚本，这个脚本会导入目标模块并调用入口函数。

当前项目为什么先推荐 python -m src？

查看答案

因为当前实际源码包名是 src，而不是 README 和脚本入口中期待的 jcode。
