# 上下文压缩对比展示设计

## 目标

在 Web 前端让用户看清一次模型调用前后的上下文压力变化，以及本次实际被压缩或移出的内容；同时保持 Run 时间线简洁。

## 展示位置与层级

- 压缩信息放在对应的模型步骤内部，每个模型步骤最多发生一次压缩，因此最多显示一张压缩卡。
- 压缩卡默认折叠，折叠状态只显示压缩状态。
- 0 档也显示压缩卡，但只显示压缩前信息；折叠状态显示压力和本次总输入 token。
- 1 至 4 档展开后显示完整的容量对比、token 差值、内容差值和结果。
- Run 顶部只显示一段汇总文本，按档位统计次数，并单独注明降级次数，不重复列出详情。

## 事件规则

- 0 档不发送 `context_compression_compared`，使用现有上下文构建事件中的数据生成 `before` 卡片。
- 1、2、3、4 档均发送一次 `context_compression_compared`，不以最终是否成功释放 token 作为发送条件。
- 一轮最多发生一次压缩，一个模型步骤只对应一个压缩对比事件，不设计多次事件合并逻辑。
- 4 档 `fallback` 仍计为 4 档压缩，机器状态为 `fallback`，界面文案固定为“降级为规则压缩”。
- 1 档没有实际释放 token 时仍发送 `applied` 事件，释放量为 `0`，内容差值为空数组。

## 事件结构

事件固定包含 `run_id`、`step_id`、`pressure_level` 以及以下分组：

```json
{
  "before": {
    "fixed_items": {},
    "total_input_tokens": 0,
    "output_reserved_tokens": 0,
    "safety_margin_tokens": 0,
    "remaining_capacity_tokens": 0,
    "pressure_ratio": 0,
    "pressure_level": 0
  },
  "after": {},
  "delta": {
    "fixed_items": {},
    "total_released_tokens": 0
  },
  "content_changes": [],
  "result": {
    "status": "applied",
    "label": "",
    "trigger": "",
    "summary_source": "",
    "artifact_ref": ""
  }
}
```

- `before`、`after` 的固定项 token 使用同一组项目名称，便于逐项比较。
- `delta` 的固定项使用“后减前”，正数表示增加，负数表示减少；总释放量使用正数表示释放规模。
- `fallback` 记录规则压缩后的实际 `after` 和 `delta`，不得伪造语义压缩结果。
- `content_changes` 列出全部发生变化的条目，不设数量上限，不分页，不显示“另有 N 项”。
- 每条内容差值包含 `change`、`category`、`turn`、`tool_name`、`summary`、`file_ref`；只列被压缩或移出的内容，不重复列出保留内容。
- `summary` 后端完整保存，前端完整展示，不截断；没有摘要时使用文件引用或明确的空值。

## Run 汇总

前端从步骤压缩卡统计档位次数和降级次数。例如：

`本次运行发生 3 次压缩：1 档 1 次、4 档 2 次（其中 1 次降级为规则压缩）。`

0 档只显示容量检查，不计入 Run 顶部的压缩次数统计。

## 异常与空值

- `content_changes` 为空时显示“本次没有移出内容”。
- 0 档不伪造 `after`、`delta` 或压缩结果。
- 审计 artifact 仅展示引用，不把压缩后的完整上下文嵌入事件或页面。

## 验收标准

1. 0 档步骤能看到折叠压缩卡，展开后只有 `before` 指标。
2. 1 至 4 档步骤能看到完整前后指标、逐项 token 差值、总释放量和全部内容差值。
3. 4 档回退明确显示“降级为规则压缩”，并计入 4 档及降级次数。
4. 1 档释放量为 0 时仍显示对比卡，释放量显示为 `0`。
5. Run 顶部只显示统计汇总，不重复展示内容差值。
6. 新增未知事件不会自动出现在前端时间线中。
