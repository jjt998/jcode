# 网页会话无感增量刷新实施计划

## 一、目标与非目标

### 目标

1. SSE 新事件到达时，页面无整体闪动，不重建用户正在查看的 DOM。
2. 展开的步骤、完整上下文审计、内部滚动条、文本选区和焦点保持不变。
3. 用户位于消息底部时，新增步骤、工具结果和最终答案自动跟随末尾。
4. 用户位于历史位置时，保持当前视觉锚点，并显示消息区正中下方、距底 16px 的小型向下箭头。
5. 点击向下箭头后，以约 180ms 平滑滚到底部并恢复自动跟随。
6. 首次加载和会话切换允许全量建立 DOM，并在加载完成后滚到末尾。
7. 重复、乱序、重连补发事件不会创建重复轮次、步骤或工具项。

### 非目标

- 不改变后端会话协议、运行逻辑和步骤业务含义。
- 不改变现有对话排序、`turn_id` 归属和历史数据修复规则。
- 不引入新的前端框架或状态管理依赖。

## 二、当前问题定位

当前实时事件路径最终都会调用 `renderTurns()`。该函数虽然尝试复用轮次节点，但活动轮次内容变化时仍可能创建新节点；一旦替换外层 turn，内部 `<details>`、审计 `<pre>` 和滚动状态都会丢失。此前还出现过旧节点未清理导致重复显示，以及滚动锚点找不到后跳到顶部的问题。

因此本次不能继续扩展“整轮次签名比较 + 整轮次替换”，必须把渲染拆成首次全量构建和实时分层同步两条路径。

## 三、总体架构

### 3.1 状态层

负责接收并合并 API、SSE 和重连事件，不直接操作 DOM。

- 维护 `state.turns`、`eventIds`、每个 turn 的 `stepMap`。
- 根据稳定 ID 合并事件，重复事件只覆盖同一对象。
- 记录当前会话和事件流代数，旧会话事件直接丢弃。
- 将高频事件加入待渲染队列，并请求下一帧同步。

### 3.2 DOM 同步层

负责把状态差异映射为最小 DOM 变化。

- 首次加载调用 `buildAllTurns()`，创建完整结构。
- 实时事件调用 `syncTurn(turn)`，只更新目标 turn。
- `syncStep(turn, step)` 只更新步骤已有节点，新增步骤才创建节点。
- 工具调用、详情块、审批和最终答案均按稳定 ID 增量创建或更新。
- 禁止实时路径调用 `replaceChildren()`、`innerHTML = ...` 重建已有 turn。

### 3.3 滚动控制层

负责主消息区的跟随、锚点和新内容提示，与 DOM 同步层解耦。

- 维护 `followLatest`、`scrollAnchor`、`pendingNewContent`。
- 监听用户滚动，区分用户滚动和代码主动滚动。
- 跟随模式自动滚底，阅读模式恢复锚点。
- 管理向下箭头的显示、隐藏和点击滚动。

## 四、详细执行步骤

### 阶段 1：建立稳定 DOM 索引

1. 为 turn、step、tool call、详情块定义稳定 DOM ID 或 `data-*` 标识。
2. 建立 `domIndex`：`turnId -> turnElement`、`stepId -> stepElement`。
3. 为步骤标题、状态、耗时、工具数量、过程文本等动态字段保留独立元素引用。
4. 为“正在推理中”建立每个 turn 唯一的状态节点，不允许通过文本搜索重复创建。
5. 为最终答案、审批区和错误信息建立唯一节点键。

### 阶段 2：拆分首次渲染与实时同步

1. `loadTurns()` 完成数据整理后调用全量构建函数。
2. 全量构建前清理当前会话 DOM、索引和会话级滚动状态。
3. 全量构建结束后设置 `followLatest = true`，在下一帧滚动到消息末尾。
4. SSE 的 `step_patch`、审批、终态事件不再调用全量渲染函数。
5. 事件处理只更新状态并将目标 turn 标记为 dirty。
6. 使用 `requestAnimationFrame` 执行一次 `flushDirtyTurns()`，逐个同步 dirty turn。

### 阶段 3：实现 turn 级增量同步

1. 按 `renderTurnId(turn)` 查找既有 turn 节点。
2. 不存在时创建一次完整 turn，并插入排序位置。
3. 已存在时保留外层 `<article>`，只同步用户消息、步骤容器、审批区、最终答案和状态节点。
4. 用户消息内容未变化时不触碰对应节点，避免选区和焦点丢失。
5. 状态变化只更新状态文本、状态样式和必要的状态节点。
6. 删除内容时只删除对应子节点，不删除整个 turn。

### 阶段 4：实现 step 级增量同步

1. 以 `step_id` 查找步骤 `<details>`。
2. 新步骤按 `compareSteps()` 插入正确位置。
3. 已有步骤只更新状态、时间、耗时、过程内容和工具数量等文本节点。
4. 步骤展开状态由现有节点自然保留，不重新设置 `open`，除非该节点首次创建。
5. 完整上下文审计详情只在首次出现时创建；已有详情只更新内容，不替换外层容器。
6. 工具调用以 `tool_id` 查找并更新；新工具追加到工具列表尾部。
7. 步骤状态为 `running` 的 turn，在时间线末尾维护唯一“正在推理中”节点。
8. turn 进入 `waiting_approval`、`completed`、`failed`、`aborted` 或 `stopped` 时移除该节点。

### 阶段 5：实现滚动状态机

定义以下状态：

```text
INITIAL_LOADING -> FOLLOW_LATEST
FOLLOW_LATEST --用户向上滚动--> READING_HISTORY
READING_HISTORY --用户接近底部--> FOLLOW_LATEST
READING_HISTORY --收到新内容--> READING_HISTORY + 显示向下箭头
点击向下箭头 -> 平滑滚底 -> FOLLOW_LATEST
会话切换 -> INITIAL_LOADING
```

执行规则：

1. 底部判定阈值暂定为 24px。
2. 用户滚动事件中，距底不超过阈值则设置 `followLatest = true`，否则设置为 `false`。
3. 代码主动设置 `scrollTop` 时设置 `programmaticScroll = true`，忽略该次滚动事件对跟随状态的影响。
4. 非跟随更新前记录稳定锚点：首个可见 turn、步骤或详情块的 ID 及相对像素偏移。
5. DOM 同步后恢复锚点；若锚点被删除，回退到所属 turn，再回退到消息区当前相对位置。
6. 跟随模式下 DOM 同步完成后在下一帧设置 `scrollTop = scrollHeight`。
7. 主消息区设置 `overflow-anchor: none`，防止浏览器原生锚定与应用逻辑冲突。
8. 内部审计容器不参与主消息区锚点计算，不主动改变其 `scrollTop`。

### 阶段 6：实现向下箭头提示

1. 在消息区容器内增加一个绝对定位按钮，水平居中，距底 16px。
2. 按钮只使用向下箭头图标，不显示文字和数量。
3. 按钮不占文档流，不改变消息区高度和滚动条范围。
4. 非跟随模式收到会改变内容高度的事件时显示按钮。
5. 用户滚到底部、切换会话、无新增内容或点击按钮后隐藏按钮。
6. 点击按钮调用 `scrollTo({ top: scrollHeight, behavior: "smooth" })`，目标时长约 180ms。
7. 点击开始时立即设置 `followLatest = true`，滚动结束后再次校正到底部。
8. 增加 `aria-label="跳转到最新内容"`、键盘焦点样式和 Enter/Space 操作。
9. 按钮显示和隐藏只切换 `visibility`、`opacity` 和 `pointer-events`，不触发消息区重排。

### 阶段 7：事件批处理与竞态防护

1. `handleRunEvent()` 只负责校验来源、去重和合并状态。
2. 同一动画帧内多个事件只触发一次 DOM flush。
3. 事件按 `event_cursor` 维护最后处理位置，过期事件不回退状态。
4. 新步骤事件和步骤补丁同帧到达时，先建立节点再更新字段。
5. 会话切换递增 `selectionEpoch`，所有异步响应和旧 SSE 回调校验代数。
6. 旧事件不得修改新会话的 `state.turns`、`domIndex` 或滚动状态。
7. 运行结束后拒绝普通事件将状态重新改为 `running`。

## 五、风险与预防

| 风险 | 预防措施 |
| --- | --- |
| 活动 turn 被整体替换 | 实时路径禁止调用 turn 级全量构建 |
| 同一节点重复显示 | 所有层级使用稳定 ID 和唯一索引 |
| 阅读位置跳顶 | 非跟随模式使用稳定锚点和偏移恢复 |
| 底部不跟随 | 维护持久 `followLatest`，同步后下一帧滚底 |
| 审计内部滚动丢失 | 复用详情和 `pre` 节点，不替换外层容器 |
| 文本选区或焦点丢失 | 内容未变化时不触碰节点；输入区永不重建 |
| 浏览器滚动锚定冲突 | 主消息区设置 `overflow-anchor: none` |
| 高频事件闪动 | `requestAnimationFrame` 合并 dirty turn |
| 重连事件重复 | 事件 ID、游标和层级 ID 三重幂等 |
| 会话切换串流污染 | 校验 project、session、epoch 和 source |
| 箭头遮挡内容 | 绝对定位并增加消息区底部安全内边距 |
| 平滑滚动中继续收到事件 | 保持跟随状态，批处理后重新校正末尾 |
| 运行结束误显示推理中 | 状态节点只由严格状态机管理 |

## 六、测试计划

### 单元测试

1. `renderTurnId()` 对 pending、web run、jcode run 和 history turn 返回稳定唯一值。
2. 相同 `step_id` 的补丁只更新一个步骤节点。
3. 相同 `tool_id` 的补丁只更新一个工具节点。
4. 事件游标倒退或事件 ID 重复时不触发新增 DOM。
5. 状态转换只在 `running` 时显示“正在推理中”。

### 浏览器集成测试

1. 首次加载会话后消息区滚到末尾。
2. 切换会话后全量建立新 DOM 并滚到末尾。
3. 非底部阅读时收到步骤更新，主 `scrollTop` 和首个可见锚点不变。
4. 底部阅读时收到步骤、工具结果和最终答案，始终保持在底部。
5. 展开完整上下文审计并滚动内部内容，收到补丁后 `open` 和内部 `scrollTop` 不变。
6. 正在输入或选中文本时收到事件，焦点和选区不丢失。
7. 非底部收到新内容时只显示一个向下箭头，按钮位于水平中心、距底 16px。
8. 点击向下箭头后约 180ms 平滑滚到末尾并隐藏按钮。
9. 连续 20 个事件在一帧内合并，不出现重复轮次或闪动。
10. 重连补发、乱序事件和旧 SSE 尾事件均不污染当前会话。
11. 窗口缩放、顶部/输入区拖拽后，跟随和阅读两种模式都保持正确。

### 静态检查

- `node --check src/app/web_static/app.js`
- `git diff --check`
- 使用项目指定解释器运行相关 Python 测试。

## 七、实施顺序与交付物

1. 先完成 DOM 稳定 ID 和索引层。
2. 再实现首次全量构建与实时增量同步分离。
3. 再实现步骤、工具、审计详情的层级更新。
4. 再接入滚动状态机和锚点恢复。
5. 最后加入向下箭头、键盘交互和样式。
6. 完成单元、浏览器集成和静态检查后更新两份 Bug 文档的验证结果。
7. 启动本地 Web 服务做人工验收，验收后停止服务，不提交 Git commit。

## 八、验收标准

只有同时满足以下条件才算完成：

- 新事件到达时消息区无整体闪动。
- 用户展开的审计内容不折叠，内部滚动位置不改变。
- 非底部阅读视角不被打断，不跳到顶部或其他位置。
- 底部阅读会持续跟随最新内容。
- 非底部时向下箭头只出现一个，位置和尺寸符合要求。
- 点击箭头后约 180ms 到达底部并恢复跟随。
- 不产生重复轮次、步骤、工具项或状态节点。
- 会话切换、重连、窗口调整和运行终态均通过测试。
