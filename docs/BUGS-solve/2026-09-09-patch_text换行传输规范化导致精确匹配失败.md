# patch_text 换行传输规范化导致精确匹配失败：方案合并记录

本文合并 2026-09-08 与 2026-09-09 两次方案。日期区分的是方案演进，不是两个并行实现。

## 2026-09-08：第一阶段方案

当时确认的措施是：

- `read_file` 和 `apply_patch` 统一使用原始 UTF-8 字节与 `utf-8-sig` 解码，保留 CRLF/LF。
- `read_file` 保存 `newline` 与 `utf8_bom` 元数据。
- `apply_patch` 失败时报告文件换行格式、old_text 是否含换行和 BOM 状态。
- schema 明确 `old_text` 必须逐字取自最近一次 `read_file`。
- 不做模糊匹配或自动替换。

该阶段已完成底层读取一致性和失败诊断，但没有解决模型生成工具参数时将 CRLF 规范化为 LF 的问题，因此跨行补丁仍可能失败。

## 2026-09-09：修订后的最终方案

### 1. 补丁匹配支持换行等价

`apply_patch` 保持 exact 匹配语义，但在匹配阶段允许以下两种表示互相转换：

- LF `\n`
- CRLF `\r\n`

执行顺序：

1. 先按原始 `old_text` 精确匹配。
2. 原始匹配为 0 次且文本包含换行时，再将 `old_text` 的 LF/CRLF 统一为目标文件换行格式后匹配。
3. 规范化后必须恰好匹配 1 次；0 次或多次仍然返回错误。
4. 替换后的 `new_text` 按目标文件原有换行格式写回。

只放宽换行表示，不放宽任何其它字符差异。

### 2. 增强模型可见诊断信息

`read_file` 返回正文头部增加：

```text
newline: crlf|lf|mixed|none
utf8_bom: true|false
```

这两个字段同时保存在 metadata，供审计和问题定位使用。

## 统一安全边界

- 不把空格或缩进差异视为等价。
- 不做大小写不敏感匹配。
- 不做模糊匹配或相似度匹配。
- 不自动选择多个候选匹配。
- 不在匹配失败时静默改写文件。
- 不因为 CRLF 兼容而改变目标文件原有换行格式。

## 验证要求

- LF old_text 匹配 CRLF 文件并成功写回 CRLF。
- CRLF old_text 匹配 CRLF 文件并成功写回 CRLF。
- LF 文件维持 LF。
- 内容或缩进改变时仍返回匹配失败。
- 规范化后出现多次匹配时仍返回非唯一错误。
- `read_file` 正文可见 newline 与 utf8_bom 信息。

## 最终结论

2026-09-08 的底层字节读取和诊断措施继续保留；2026-09-09 新增的 LF/CRLF 传输等价匹配是对早期方案的正式修订。现行实现必须以本合并文档为准。
