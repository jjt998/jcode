# 历史会话步骤占位与顺序错乱

## 解决方案

1. 服务端以 `session.history` 中每个运行首次出现的位置作为会话顺序，未出现在历史中的运行稳定追加到末尾，并向前端提供 `sequence`。
2. 前端加载历史数据和接收实时 `step_patch` 时统一按步骤索引、时间戳和步骤 ID 排序；轮次按服务端 `sequence` 排序。
3. 空步骤占位改为基于实际状态展示：运行中，或已有用户消息但尚无最终答案时显示“等待步骤生成”。
4. 增加服务端回归测试，验证反向 `run_ids` 不能重排历史对话。
5. 历史项缺少 `run_id` 时按明确 `turn_id` 归属；`turn_id: "current"` 的中途确认消息归属到后续同一运行，避免生成独立空轮次。
6. 运行中且已有步骤时，在步骤列表末尾展示“正在推理中”；仅 `running` 状态展示，避免完成、失败、中止或等待用户确认时误报运行中。
