# 历史会话步骤占位与顺序错乱

## 解决方案

1. 服务端以 `session.history` 中每个运行首次出现的位置作为会话顺序，未出现在历史中的运行稳定追加到末尾，并向前端提供 `sequence`。
2. 前端加载历史数据和接收实时 `step_patch` 时统一按步骤索引、时间戳和步骤 ID 排序；轮次按服务端 `sequence` 排序。
3. 空步骤占位改为基于实际状态展示：运行中，或已有用户消息但尚无最终答案时显示“等待步骤生成”。
4. 增加服务端回归测试，验证反向 `run_ids` 不能重排历史对话。
5. 历史项缺少 `run_id` 时按明确 `turn_id` 归属；`turn_id: "current"` 的中途确认消息归属到后续同一运行，避免生成独立空轮次。
6. 运行中且已有步骤时，在步骤列表末尾展示“正在推理中”；仅 `running` 状态展示，避免完成、失败、中止或等待用户确认时误报运行中。
7. 消息区按轮次 ID 复用既有 DOM 节点，只更新内容变化的轮次；刷新前保存首个可见轮次的滚动锚点，用户不在底部时恢复该位置，只有用户原本在底部才自动跟随新内容。移除“等待步骤生成”占位。
8. 增量同步改为目标节点集合：移动本次需要的节点后，删除所有不在集合内的旧节点，保证内容变化不会残留旧副本；统一使用容器 `children` 获取直接轮次节点，确保滚动锚点在浏览器中稳定可用。

## 动态阅读内容无感更新修复（2026-09-07）

- 上下文审计和工具完整输出在加载完成后设置 `data-loaded="true"` / `data-content-loaded="true"`，作为展示内容所有权标记。
- `morphNode()` 只同步已加载动态节点的外层属性，不再用新的占位正文覆盖用户正在阅读的内容。
- 动态正文使用独立滚动 key 纳入详情状态快照，更新后恢复内部 `scrollTop`；详情块继续使用稳定 `data-state-key`。
- 后端 `WebRunManager._bind_run_store()` 为每个步骤维护快照指纹，相同 `step_patch` 不再重复发送；该优化降低刷新频率，不替代前端正文保护。

## 下一阶段完整实施计划

### 一、渲染层

- 保留首次加载/会话切换的全量构建路径，完成后滚到消息末尾。
- 将实时更新改为状态层、DOM 同步层分离：状态先合并，DOM 只同步变化节点。
- 轮次、步骤、工具调用和详情块使用稳定 ID；禁止通过替换整个 turn 来更新步骤。
- 已展开的 `<details>`、完整上下文审计和内部 `pre` 滚动容器始终复用原节点。

### 二、事件层

- SSE 事件按事件 ID和 `event_cursor` 去重。
- 新步骤先创建节点，再应用后续补丁；重复补丁只更新同一节点。
- 通过 `requestAnimationFrame` 合并一帧内的多个事件，避免连续重排。
- 会话切换后丢弃旧请求和旧 SSE 尾事件，防止跨会话污染。

### 三、滚动层

- 维护持久的 `followLatest`，不在每次刷新时临时猜测。
- 底部状态：新内容、步骤高度变化和最终答案出现时自动滚到底部。
- 阅读状态：保存稳定锚点及像素偏移，更新后恢复原视角。
- 主消息区关闭浏览器自动滚动锚定，内部审计滚动区保留原生行为。
- 首次加载和切换会话完成后滚到末尾，并重置当前会话的跟随状态。

### 四、底部新内容提示

- 非底部阅读时收到新内容，显示消息区水平正中、距底 16px 的小型向下箭头按钮。
- 按钮使用无障碍名称“跳转到最新内容”，支持键盘操作，不显示数量，不占文档流。
- 点击后使用约 180ms 平滑滚动到底部，隐藏按钮并恢复 `followLatest`。
- 用户自行滚到底部、切换会话或没有新增内容时隐藏按钮。

### 五、回归验证

1. 展开完整上下文审计后收到步骤补丁，展开状态和内部滚动位置不变。
2. 非底部阅读时收到连续事件，主滚动位置和可见锚点不变。
3. 底部阅读时收到新步骤、工具结果和最终答案，始终跟随末尾。
4. 点击向下箭头后按约 180ms 平滑滚动到底部，按钮隐藏并恢复跟随。
5. 高频事件合并为单帧更新，不产生闪动或重复节点。
6. 断线重连、乱序和重复事件不重复创建轮次、步骤或工具项。
7. 快速切换会话时，旧会话事件不污染新会话，新的会话首次加载滚到末尾。
8. 窗口缩放、顶部/输入区拖拽和终态事件不破坏阅读锚点。
