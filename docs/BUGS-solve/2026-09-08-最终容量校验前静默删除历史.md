# 最终容量校验前静默删除历史

## 解决方案

删除 `ContextManager._fit_optional_history` 及其调用，并移除 `ContextBudgetCandidate` 在该路径中的依赖。最终 Provider 输入仍通过统一序列化快照计量，`validate_final_capacity` 继续执行硬容量校验。

## 新流程

```text
压力级别微压缩
-> Level 4 语义摘要（如触发）
-> 编译最终 Provider 输入
-> 真实 token 容量校验
-> 超限直接抛出 FinalContextExceedsWindowError
```

## 验证

增加回归测试，确认存在旧历史时，最终容量超限不会删除 session 中的旧 turn，而是直接抛出 `FinalContextExceedsWindowError`。
