# 新会话区未显示模型推理配置

## 修复目标

空会话区直接展示 JCode 全局配置中的默认模型、推理开关和思考强度，并允许这些选择成为首次创建 session 时的正式配置。

## 实现方案

1. Web 后端新增只读的 `/api/model-configuration` 接口，返回 `default_model_profile` 和无密钥的 `model_profiles` 快照。
2. 前端加载项目列表时同时读取全局模型配置。
3. 选中项目后，无论是否存在 session，都先用全局默认配置渲染模型控件。
4. 空会话区切换模型时先更新本地推理控件，不因缺少 session 提前退出。
5. 空会话区首次发送时，先创建 session，再通过现有模型切换接口写入界面当前选择，最后发送消息。
6. 已有 session 继续以 session 自身的 `active_model_profile` 和 `model_options` 为准。

## 失败语义

全局模型配置接口或首次模型设置失败时，前端沿用现有请求错误路径并停止发送，不跳过配置、不替换选择、不静默使用其他模型。

## 验证标准

- 无 session 项目打开后，模型、推理和思考强度立即显示全局默认值。
- 首次发送前修改配置，新建 session 持久化对应选择。
- 已有 session 的模型选项展示和切换行为不变。
- Python 测试与前端 JavaScript 语法检查通过。
