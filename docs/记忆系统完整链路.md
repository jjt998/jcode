# JCode 记忆系统完整链路

本文以当前实现为准，说明 WorkingMemory、Daily Log、Durable Memory 与 Dream 整理之间的数据流。

## 1. 三层模型

```text
WorkingMemory（当前运行控制面）
  -> Daily Log（每轮过程记录）
  -> Durable Memory（稳定结论与主题索引）
```

WorkingMemory 服务当前上下文和工具策略；Daily Log 记录当天过程；Durable Memory 只沉淀可长期复用的结论。

## 2. WorkingMemory

`src/memory/working.py:WorkingMemory` 使用 `jcode.layered_memory.v2`，保存任务目标、约束、最近文件、文件 freshness、读取范围与计数、工具观察、todo、子 Agent 结果、检索结果、安全提示、运行模式和 Level 4 冷文件索引。

成功 `read_file` 会更新 freshness 和读取计数；写入或 patch 后，Agent 将依赖旧文件的历史证据标记 stale。`render()` 只输出控制信息和索引，不复制完整文件正文。

## 3. 每轮维护

`src/memory/consolidation.py:maintain_after_turn()` 在回合结束后调用 `DurableMemoryStore.promote_from_turn()`：

```text
最终回答 -> Daily Log -> notes.jsonl -> memory audit
```

候选内容由用户请求和最终回答组成。`src/memory/safety.py:looks_sensitive()` 会在写入前过滤密钥、token、password、secret 等敏感文本。

## 4. Daily Log

`src/memory/journal.py` 将日志写入 `.jcode/memory/logs/YYYY/MM/YYYY-MM-DD.md`，每条包含时间和来源（例如 `turn_summary`）。`iter_daily_log_entries()` 按日期读取日志；Daily Log 是后续整理输入，不是最终知识库。

## 5. Durable Memory

`src/memory/durable.py:DurableMemoryStore` 管理：

```text
.jcode/memory/
  MEMORY.md
  notes.jsonl
  topics/project-conventions.md
  topics/key-decisions.md
  topics/dependency-facts.md
  topics/user-preferences.md
```

`add()` 追加安全文本到 `notes.jsonl`；`retrieve()` 做有限词项匹配；`consolidate_daily_logs()` 清洗日志、分类主题、去重并更新索引与主题文件，每个主题最多保留最近 50 条。

## 6. 检索回注

`src/memory/retrieval.py:retrieve_into_working_memory()` 将 Durable Memory 命中结果写入 `WorkingMemory.retrieved_memory`。下一次 `ContextManager.build()` 把它们放入 working memory 区域，不伪装成用户消息或稳定系统规则。

## 7. Dream 子 Agent

`src/runtime/agent.py:run_dream()` 调用受限 Dream 流程。Dream 使用 `dream` Tool Profile，只能读写 `.jcode/memory/`，不能修改普通源码；报告写入 `.jcode/memory/dream_reports/*.json`。运行前后比较 memory snapshot，并在审计中记录实际 changed_files。

## 8. Session 与 Checkpoint

Session schema v5 持久化 WorkingMemory 快照；Checkpoint schema v3 保存 task、working memory、文件 freshness、todo、workspace fingerprint 和 worker 引用。恢复只把状态回注 WorkingMemory，不改写历史事实；长期记忆仍由 DurableMemoryStore 独立管理。

## 9. 排查入口

先检查 run 的 `working_memory` 和 `context_built`，再检查 `memory_maintained` 或 report 中的 audit，最后核对 `.jcode/memory/logs/`、`notes.jsonl`、`topics/` 和 `dream_reports/`。若未沉淀，重点检查敏感过滤、空文本判断、主题去重和 Dream 的 changed_files。
