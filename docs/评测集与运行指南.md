# JCode 评测集与运行指南

本文以当前 `eval/` 实现为准，说明评测 Case、运行证据、离线评分和 CI 校验流程。当前评测协议版本为 `1.0`，manifest 为 `eval/manifests/v1.json`。

## 1. Case 清单

当前 manifest 收录 24 个版本化 Case：

| 类别 | 数量 | 覆盖范围 |
| --- | ---: | --- |
| `checkpoint_resume` | 6 | 有效恢复、文件过期、工作区漂移、不兼容 checkpoint、shell/工具链部分成功 |
| `context_compression` | 4 | 正常压力、重复压缩、大输出、摘要失败 |
| `layered_memory` | 4 | Working Memory、Daily Log、Durable Recall、Dream 安全隔离 |
| `tool_governance` | 10 | 未知工具、参数校验、路径逃逸、读写前置、新鲜度、重复调用、超时、中止和副作用 |

权威清单是 `eval/manifests/v1.json`，场景文件位于 `eval/cases/<category>/`。评测基础设施测试位于 `eval/tests/`，产品测试仍位于 `test/`。

## 2. 目录与产物

```text
eval/
  cases/                         # JSON Case 定义
  manifests/v1.json              # 版本化清单与默认超时
  schema/                        # Case、RunRecord、Score JSON Schema
  cli.py                         # list / validate / run / score / replay / summary
  loader.py / protocol.py        # Case 与 RunRecord 协议
  runner.py                      # workspace 隔离、子进程运行、证据复制
  scorer.py                      # 离线谓词评分和红线判断
  replay.py / summary.py         # trace 回放与结果汇总
  tests/                         # 评测基础设施测试
  reports/                       # 本地运行产物，不提交真实报告
```

每次运行写入 `eval/reports/<case-id>/<run-id>/`，包括 `run_record.json`、`score.json`，以及复制的 `.jcode` 证据目录。证据目录可能包含 `trace.jsonl`、`report.json` 和 `checkpoint.json`。

## 3. Case 协议

每个 Case JSON 必须包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `case_id` | 全局唯一标识，例如 `tool_governance-t3-path-escape` |
| `eval_version` | 评测协议版本，当前为 `1.0` |
| `category` | 四个评测类别之一 |
| `scenario` | 类别内编号，例如 `R1`、`C2`、`M4`、`T9` |
| `description` | 场景和故障边界说明 |
| `prompt` | 发送给 JCode 的任务文本 |

可选字段为 `workspace_fixture`、`model_profile`、`allowed_tools`、`write_scope`、`fault_injection`、`acceptance_predicates`、`forbidden_behaviors` 和 `config`。定义以 `eval/schema/case.schema.json` 与 `eval/protocol.py:EvalCase` 为准。缺少必填字段时，`validate` 失败，不自动补默认值。

`fault_injection` 只接受 Case 明确声明的 `external_file_change`、`workspace_drift` 等类型，目标路径必须在隔离 workspace 内。Case 文件不得保存 API 密钥。

## 4. RunRecord 与评分

`EvalRunner` 为每个 Case 创建独立 workspace，记录初始和最终 workspace 指纹，运行 JCode 子进程，并复制 `.jcode` 证据。`RunRecord` 保存 Case、评测/运行器/评分器版本、JCode revision、run ID、时间、`final_status`、变更文件、工具尝试、checkpoint、上下文、验证、标准输出/错误和 trace 快照。

`OfflineScorer` 只读取持久化 Case、RunRecord 和证据，不重新执行工具。支持的验收谓词：

| 谓词 | 判断内容 |
| --- | --- |
| `final_status_is` / `exit_code_is` | 终态或进程退出码相等 |
| `changed_files_include` / `changed_files_exclude` / `changed_files_empty` | 工作区变更路径校验 |
| `stdout_contains` / `stdout_not_contains` / `stderr_contains` | 输出文本校验 |
| `evidence_exists` | 证据索引中存在指定名称 |
| `checkpoint_status_is` / `checkpoint_field_equals` | checkpoint 状态或字段校验 |
| `trace_event_exists` / `trace_event_count_at_least` | trace 事件存在性或数量校验 |
| `report_field_equals` | report 字段值校验 |

所有谓词通过得到 `task_success`。若命中 `forbidden_behaviors` 红线（如 `unauthorized_write`、`silent_side_effect`），最终 `passed` 仍为失败，并同时输出 `agent_quality`、`harness_quality` 和 `assurance`。

## 5. 命令

在仓库根目录使用项目专用 Python：

```powershell
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . list
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . validate
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . run --case checkpoint-resume-r1-valid-checkpoint --keep-workspace
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . run --category tool_governance
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . run --all
```

默认 runner timeout 为 300 秒；单个 Case 可在 `config.timeout_seconds` 中声明更短超时。运行完成后会自动生成 `run_record.json` 和 `score.json`。

对已有产物评分、回放和汇总：

```powershell
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . score --case-file eval\cases\tool_governance\T3-path-escape.json --record-file eval\reports\<case-id>\<run-id>\run_record.json --output eval\reports\<case-id>\<run-id>\score.json
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . replay --result-dir eval\reports\<case-id>\<run-id>
& 'D:\jt\ANACONDA\envs_dirs\jcode\python.exe' -m eval.cli --project-root . summary --score-file eval\reports\<case-a>\<run-a>\score.json --score-file eval\reports\<case-b>\<run-b>\score.json --output eval\reports\summary.json
```

`replay` 只读 `trace.jsonl`，输出事件统计和原始顺序，不重新执行 JCode 或工具。

## 6. CI 与安全边界

`.github/workflows/eval.yml` 在 Pull Request、推送到 `main` 和每日定时任务中安装项目，执行 `eval.cli validate`、`pytest -q eval/tests` 并再次校验 manifest。CI 只验证评测协议和基础设施；真实 Provider 运行需要本地配置和密钥，不应写入仓库。

- Runner 使用隔离 workspace，fixture 和故障注入不得越出该目录。
- 结果目录只保存脱敏后的 JCode 证据，不提交密钥、个人路径或真实业务数据。
- 不修改 `docs/改进方案/`、`docs/BUGS-after9.6/`、`docs/BUGS-solve/` 来适配评测结果。
- 评分失败时保留 RunRecord、trace 和 checkpoint，依据证据定位问题，不静默删除或覆盖失败产物。
