# 当前请求被工作记忆重复加权

## 现象

每次新 run 的用户消息既写入 user HistoryEvent，又被复制到 Working Memory 的任务字段。Working Memory 位于 History 之后，导致最新消息在 Provider 输入中重复出现并被额外强调。

真实场景中，用户在重构任务中补充“不要终止我的进程”后，模型持续围绕该约束解释和产出，而主任务推进效率明显下降。

## 根因

`JCodeAgent._begin_run()` 每个 run 都覆盖该字段，`ContextManager.build()` 又继续维护副本。该字段并不保存稳定主目标，只保存最新 run 请求，却被纳入固定上下文、checkpoint 和 Level 4 摘要。

## 影响

- 最新用户消息在 Provider 输入中重复。
- 后置 Working Memory 副本可能放大补充说明或执行约束的权重。
- 固定上下文容量重复占用。
- 持久化和摘要协议承担了没有独立业务价值的字段。
