# shell 快照漏记已有文件修改

## 问题

工具执行前后虽然都会生成 `Workspace.snapshot()`，但旧实现使用快照 key 的对称差计算变更路径，只能识别新增和删除文件。

当 shell 修改已经存在的文件时，路径在前后快照中都存在，旧实现不会比较 `(mtime_ns, size)`，因此 `changed_files` 会漏记该文件。

## 影响

- risky 工具的副作用证据不完整。
- tester 子 Agent 可能执行修改已有文件的命令，但父 Agent 无法收到对应路径。
- 依赖 `changed_files` 的 stale 证据标记不会触发。

## 触发条件

`run_shell` 或其他纳入快照比较的执行路径修改已有文件，且工具本身没有显式返回该文件。
