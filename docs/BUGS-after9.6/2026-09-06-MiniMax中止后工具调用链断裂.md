# Bug：MiniMax 中止后工具调用链断裂

## 基本信息

- 发现日期：2026-09-06
- 影响 Provider：`minimax`
- 影响协议：`openai_responses`
- 影响模型：已确认 `minimax-m3`，同一 Responses 工具协议的 `minimax-m2.7` 也存在风险
- 影响场景：一个 run 执行 abort 后，在同一 session 中启动第二个 run
- 相关真实 session：`D:\1technical_stack_study\agent_study\agent_projects\demo_test\snake_game\.jcode\sessions\20260906T065216.579223+0000-984cb0.events.jsonl`

## 现象

第二个 run 在首次或后续模型请求时失败：

```text
运行时错误: minimax responses error 400:
{"error":{"message":"invalid params, tool call result does not follow tool call (2013)","code":"invalid_prompt"}}
```

第二个 run 的终态为 `unexpected_runtime_error`，而不是正常的用户中止或可恢复状态。

## 真实证据

首个实现 run `run-3a2c9a1bdb` 在 abort 前收到最后一个原生工具调用：

```text
call_id = call_ed56f21c74f54ba6ba2d17
name = read_file
arguments = {"path":"references.md"}
```

该调用只出现在 `native_tool_calls_received` 和 session history 的 `tool_call` 中，没有对应的 `function_call_output`。随后首个 run 以 `stop_reason=aborted` 结束。

第二个 run `run-a78f68d6e8` 构建的 Responses 输入仍包含这个孤立的 `function_call`。`src/providers/request.py` 会把 session history 编译成 Responses 项，MiniMax 因此收到未闭合的调用链并返回错误码 2013。

## 根因链路

```text
模型返回 function_call
  -> _record_model_history() 先写入 tool_call
  -> 用户 abort
  -> 工具执行循环被 break，未生成 tool_result
  -> session 持久化了孤立 tool_call
  -> 下一 run 回放 session history
  -> MiniMax Responses 拒绝没有后续结果的 function_call
```

关键实现位置：

- `src/runtime/agent.py`：收到响应后先记录模型工具调用；abort 时在工具循环中断开执行。
- `src/providers/request.py`：将 history 中的 `tool_call` 编译为 `function_call`，将 `tool_result` 编译为 `function_call_output`。
- `src/providers/continuation.py`：同一 run 的原生续接项也可能保留未完成的 `function_call`。

## 为什么只在第二个 run 暴露

首个 run 的 abort 本身没有向 Provider 发出下一次请求，所以服务端不会再次校验这段历史。第二个 run 复用同一 session 的 history 时，才把“有调用、无结果”的结构提交给 MiniMax。

## 影响范围

- 同一 session 的后续 MiniMax run 可能连续失败，直到孤立调用从 history 中消失。
- 失败不是模型输出内容错误，而是客户端持久化并回放了非法 Responses 输入。
- DeepSeek 或其他较宽松的兼容实现未必立即报错，但同样可能收到语义不完整的工具链。
- 仅清理 `provider_continuation` 不足以解决本例，因为孤立调用同时已经写入通用 session history。

## 当前缺口

abort 结束 run 时没有统一的“未完成工具调用收口”步骤，也没有在新 run 构建 Responses 输入前校验每个 `function_call` 是否存在匹配的 `function_call_output`。
