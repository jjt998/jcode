# 工作区重复扫描导致首次与恢复运行耗时过长

## 现象

Harness 的 `checkpoint` 组件在首次 run 中耗时明显偏高；已有会话的第二次 run 即使只是简单问候，`run_initialize` 仍可能耗时十秒以上。

## 根因

两类耗时来自同一个问题：工作区基线扫描被重复执行。

1. 首次 run 创建 checkpoint 时，`CheckpointManager.create()` 先调用 `workspace.fingerprint()`，随后又调用 `workspace.baseline()`。两者都会递归扫描工作区并执行 Git 状态查询。
2. 后续 run 进行会话恢复评估时，checkpoint 校验、恢复上下文和 fingerprint 计算分别重复生成工作区基线。

## 影响

重复扫描放大了首次 run 的 `checkpoint` 耗时，也放大了后续 run 的 `run_initialize` 耗时，使 Harness 总耗时与实际业务复杂度不匹配。
