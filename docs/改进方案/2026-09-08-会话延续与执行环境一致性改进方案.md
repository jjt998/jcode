# 会话延续与执行环境一致性改进方案

## 1. 背景

当前 JCode 在“启动时恢复旧 session”和“同一会话内第二次及之后发送”之间存在实现分叉：前者会评估 checkpoint，后者直接创建新 run。用户视角上它们都是同一会话链路的继续，应该使用同一套工作区、文件证据和执行环境评估。

当前工作区变化主要依赖 JCode 自己写入或 patch 后调用 `_mark_stale_file_evidence()`；用户通过 IDE、Git、脚本等外部修改工作区时，后续 run 不会主动比较基线并标记旧读取证据。checkpoint 也缺少模型、Provider、reasoning、协议和工具 schema 指纹。

## 2. 冻结产品语义

同一会话中：

- 第一次发送建立 session、workspace 和 execution 基线。
- 第二次及之后的每次发送都视为 `session continuation`。
- 程序重启后加载旧 session 的第一次发送，也视为 `session continuation`。
- 这两类发送使用同一个恢复评估链路，不区分业务语义。
- 每次 continuation 仍创建新的 `TaskState` 和新的 `run_id`。

`session continuation` 不等于 Provider 原生 continuation。只有存在未完成且兼容的 reasoning/tool continuation 时，才允许继续旧的原生调用链；普通后续发送始终创建新的 run。

## 3. stale 语义

保留现有 `_mark_stale_file_evidence()`，抽取按 `changed_paths` 标记 stale 的公共入口。

调用来源统一为：

1. JCode 自己执行 `write_file` 或 `apply_patch` 成功后；
2. 恢复或后续 run 开始前完成 workspace/freshness 基线比较后。

不新增第二套 stale 数据结构。`stale` 只表示旧读取证据不能作为当前事实使用，不表示任务失败，也不表示删除数据。

历史、artifact、Working Memory 的旧记录均保留，用于审计、上下文摘要和变更追溯。模型收到 stale 证据时必须重新读取当前文件。

## 4. 统一延续评估链路

```text
发送用户请求
  -> 判断是否存在历史 run
  -> 有历史 run 时执行 SessionContinuationEvaluator
       -> workspace 基线比较
       -> hot 文件 freshness 比较
       -> execution fingerprint 比较
       -> Provider continuation 兼容性比较
       -> 生成结构化 resume_context
  -> 使用 changed_paths 标记旧读取证据 stale
  -> 创建新的 TaskState/run
  -> 写入当前 user history
  -> 构建上下文并执行
  -> 保存新的 workspace/execution baseline
```

第一次发送没有上一条基线，只建立基线；启动恢复和会话内后续发送都在创建新 run 前执行同一个 evaluator。

## 5. Workspace 基线

workspace 基线采用结构化数据，不只保存不可解释的单一字符串：

```json
{
  "root": "...",
  "git_head": "...",
  "git_branch": "...",
  "git_status": "...",
  "files": {
    "src/a.py": {"size": 1200, "mtime_ns": 123456789}
  },
  "hash": "..."
}
```

第一阶段递归收集 workspace 相对路径、大小和 `mtime_ns`，排除 `.jcode`；同时记录 Git HEAD、branch 和 status。第二阶段对 hot 文件、当前 run 读取或修改过的文件以及运行规则文件增加内容 hash，以避免仅凭 mtime/size 漏检。

当前 fingerprint 只检查根目录前 200 个一级条目，且不递归，必须移除这个边界。

评估输出至少包含：

```json
{
  "status": "partial_stale",
  "changed_paths": ["src/a.py"],
  "stale_paths": ["src/a.py"]
}
```

`changed_paths` 是基线以来变化的路径；`stale_paths` 是实际影响历史读取证据的路径。

## 6. Execution fingerprint

checkpoint 增加结构化执行环境指纹：

```json
{
  "provider": "deepseek",
  "model_profile_id": "deepseek-flash",
  "model_name": "...",
  "reasoning_enabled": true,
  "reasoning_effort": "high",
  "provider_protocol": "openai_responses",
  "tool_schema_hash": "...",
  "runtime_protocol_version": "...",
  "context_policy_version": "9.5"
}
```

工具 schema hash 必须基于当前实际暴露给模型的工具定义计算。

## 7. 恢复与兼容状态

恢复评估输出工作区、执行环境和 continuation 三组结果，不相互覆盖：

```json
{
  "session_continuation": true,
  "previous_run_id": "run-1",
  "workspace": {
    "status": "partial_stale",
    "changed_paths": ["src/a.py"],
    "stale_paths": ["src/a.py"]
  },
  "execution": {
    "status": "model_mismatch",
    "provider_changed": false,
    "model_changed": true,
    "reasoning_changed": false,
    "tool_schema_changed": false,
    "protocol_changed": false
  },
  "continuation": {
    "present": false,
    "compatible": false
  },
  "action": "start_new_run_with_reread"
}
```

建议状态：`new_session`、`session_continuation`、`full_valid`、`partial_stale`、`workspace_mismatch`、`execution_mismatch`、`continuation_incompatible`、`schema_mismatch`、`checkpoint_not_resumable`、`no_checkpoint`。

## 8. 兼容性规则

| 变化 | 无未完成 continuation | 有未完成 continuation |
| --- | --- | --- |
| model profile | 允许新 run，记录 mismatch | 禁止继续旧 continuation |
| reasoning 开关 | 允许新 run，记录 mismatch | 禁止继续旧 continuation |
| reasoning effort | 允许新 run，记录 mismatch | 禁止继续旧 continuation |
| Provider | 允许新 run，记录高风险变化 | 禁止继续旧 continuation |
| Provider 协议 | 不继续旧 continuation | 禁止继续旧 continuation |
| 工具 schema | 使用当前 schema 开新 run | 禁止未闭合工具链恢复 |
| workspace 变化 | 允许新 run，标记旧读取证据 stale | 不得依赖旧文件事实 |

不因模型变化禁止普通后续发送；只阻止不兼容的旧原生 continuation 被继续使用。

## 9. Working Memory 与历史

恢复状态必须真正进入模型可见 Working Memory，不能被 `render()` 中的重新赋值覆盖。展示采用稳定字段，不直接把 checkpoint 原始字典作为唯一信息来源：

```text
Working_Memory:
- session_continuation: true
- previous_run_id: run-1
- workspace_status: partial_stale
- changed_paths: src/a.py
- stale_paths: src/a.py
- execution_status: model_mismatch
- action: start_new_run_with_reread
```

旧 history 和 artifact 永远保留；stale 只改变模型对证据时效性的解释。

## 10. 审计事件

统一记录：

- `session_continuation_evaluated`
- `workspace_baseline_evaluated`
- `workspace_changed_detected`
- `execution_fingerprint_evaluated`
- `continuation_compatibility_evaluated`

事件至少包含 `previous_run_id`、工作区状态、`changed_paths`、`stale_paths`、执行环境差异、continuation 是否存在/兼容以及最终 action。

## 11. 禁止事项

- 不新增第二套 stale 数据结构。
- 不因外部变化删除 history 或 artifact。
- 不把旧读取正文替换成新正文并覆盖审计事实。
- 不因模型变化自动伪造 continuation 兼容。
- 不自动模糊匹配、自动修复或静默忽略执行环境差异。
- 不为无法满足兼容条件的 continuation 增加降级发送。

## 12. 验收目标

第一次发送建立基线；同一会话第二次及之后发送与启动恢复使用同一 evaluator；外部修改能通过 `changed_paths` 进入统一 stale 标记；旧证据保留且不会作为当前事实；模型/Provider/协议/工具 schema 变化可审计；不兼容 continuation 不会继续执行。
