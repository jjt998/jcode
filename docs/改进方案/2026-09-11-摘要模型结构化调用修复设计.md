# 摘要模型结构化调用修复设计

## 目标

修复 Level 4 摘要模型因 Provider 返回空文本、非 JSON 文本或请求协议不完整而持续进入规则摘要的问题。

## 方案

1. 摘要请求携带固定的 9.6 JSON Schema，要求 Provider 直接生成合法摘要对象。
2. DeepSeek 与 MiniMax 都使用各自完整的摘要请求配置；MiniMax 摘要请求同步当前模型的 reasoning 设置。
3. Responses 响应优先读取顶层 `output_text`，缺失时读取 message content 文本；不对非法内容做静默清洗。
4. JSON/schema 校验失败、HTTP/超时失败仍按既定协议最多重试三次，之后使用确定性规则摘要。
5. Level 4 没有淘汰历史、未实际调用摘要模型时，状态记录为“规则摘要”，不标记为模型降级。

## 验证

- 验证摘要请求包含结构化输出约束和 MiniMax reasoning。
- 验证两种合法 Responses 文本形态均可被解析。
- 验证非法 JSON、Provider 异常和三次重试后 fallback 语义不变。
- 运行定向测试及全量测试。
