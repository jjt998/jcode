# 删除 task_goal 重复请求字段

## 目标

当前用户请求只通过当前 turn 的 user HistoryEvent 进入 Provider，不再复制到 Working Memory、checkpoint 或 Level 4 摘要的特权字段中。

## 已确认语义

- 不新增稳定主目标字段。
- 不新增执行约束识别或自动分类。
- 不修改 History 窗口、Level 4 压缩范围及摘要其他字段的业务语义。
- `TaskState.user_request` 继续保存本 run 的原始请求，用于状态、审计和需求提取。
- 内部输出续写只使用 `internal_continuation_instruction`，不写入 History 或 Working Memory。

## 数据链路

```text
用户消息
├─ TaskState.user_request：本 run 状态与审计
└─ user HistoryEvent：唯一 Provider 用户请求
```

Working Memory v3 只保留执行约束、文件状态、工具观察、todo、恢复上下文、检索结果和运行状态等控制面数据。

## 协议变更

- Session schema：v6。
- Working Memory schema：`jcode.layered_memory.v3`。
- Checkpoint schema：v5。
- Compact summary schema：9.6，共 10 个字段。

旧协议不迁移、不兼容、不自动过滤；版本不一致时沿用现有失败出口。

## 验收标准

- 运行时代码不存在该重复字段的读写。
- 当前请求在 Provider input 中只出现一次。
- checkpoint、Working Memory 和 compact summary 均不再包含该字段。
- Dream 子 Agent 仍通过 `child.ask(prompt)` 的 user HistoryEvent 获得任务。
- 全量测试通过。
