# 恢复上下文变更路径模型投影冻结方案

## 1. 背景

恢复上下文原样携带完整 `changed_paths`。当工作区安装 Node 依赖时，`node_modules` 会产生大量路径，导致下一次 run 的 Provider 输入异常膨胀。

## 2. 冻结目标

保留工作区变化对 JCode 本地判断的完整性，同时避免无决策价值的依赖文件路径进入模型上下文。

## 3. 冻结设计

恢复差异只保留两个视图：

- 本地完整变更路径 `changed_paths`；
- Provider 可见的最小路径投影。

完整 `changed_paths` 继续用于工作区变化判断、旧读取证据 stale 标记、continuation 兼容性判断和现有运行审计，不进入 `WorkingMemory.render()`。

Provider 可见路径定义为：

```text
visible_changed_paths = changed_paths ∩ (历史 read_file 路径 ∪ 当前 hot 文件路径)
```

模型上下文规则：

- 有可见路径时，展示这些完整路径；
- 有其他未投影变化时，追加一句“工作区发生了变化。”；
- 只有其他变化时，只展示这句话；
- 没有变化时，不展示工作区变化信息。

历史 `read_file` 路径只指实际产生文件证据的读取路径。`search` 扫描到的全部来源文件不自动视为模型侧已读路径。

## 4. 明确不加入的机制

- 目录级统计、文件数量汇总和变更类型统计；
- 代表路径采样；
- 完整路径 artifact 引用；
- 分页或按前缀查询工具；
- 本方案专用的内容哈希；
- 固定忽略 `node_modules` 或缓存目录；
- 第二套 stale 数据结构。

## 5. 验收标准

- `node_modules` 大规模变化时，Provider 只收到一句“工作区发生了变化。”；
- 已读或 hot 文件变化时，Provider 收到对应完整路径；
- 已读文件被删除时，仍能展示该历史路径；
- 本地 stale 标记仍接收完整 `changed_paths`；
- `search` 扫描大量文件时，不会把全部扫描来源注入 Provider 输入；
- 恢复上下文大小不随未读依赖文件数量线性增长。
